# Technical Writing Portfolio — API Documentation

Hi, I'm Sammy. I write clear, structured API documentation — reference docs, quick starts, and rewrites of documentation that's technically accurate but hard to use.

The four samples below cover the situations you'd actually hire a technical writer for: fixing documentation that's fallen behind, documenting an API that has none, and designing docs from a spec before a product exists.

## Samples

### 1. [CelesTrak GP Data API — Rewrite](./celestrak-gp-api-reference.md)
A satellite tracking API with accurate but narratively-organized documentation. Rewritten into a standard reference: quick start, parameter table, format options, and error handling — with the original text shown alongside for comparison.

### 2. [Municipal Money API — Rewrite](./municipal-money-api-reference.md)
South Africa's National Treasury API for municipal financial data. The official docs bury the actual query syntax under thousands of lines of data dictionary. This rewrite separates the two: a compact "how to query" reference, plus a pointer to the official docs for the (unavoidably long) field list.

### 3. [Frankfurter Currency API — Documented from Scratch](./frankfurter-api-reference.md)
A live currency exchange API, documented as if writing its first-ever reference. Every request and response shown was tested against the production API before being included — nothing copied from elsewhere.

### 4. [TaskFlow API — Designed and Documented from a Spec](./taskflow-api-reference.md)
A fictional task management API, built and documented from nothing. Demonstrates the design side of the job: choosing a pagination strategy, structuring a consistent error format, and deciding what belongs in v1 versus a later version.
